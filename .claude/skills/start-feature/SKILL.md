# Starting a feature

Every task that changes code gets its own git worktree and **dev slot**, unasked. The slot gives the
work a plugin name, a plugin id and a relay port of its own, so in Figma the user sees the stable
**Figma Design Relay** and one **Figma Design Relay (Dev: <name>)** per feature in progress, and
nothing a half-built feature does can reach the stable relay. Docs-only work may stay on a plain
branch; it has nothing to run.

|                   | Main checkout (stable) | Feature worktree (dev slot)                          |
| ----------------- | ---------------------- | ---------------------------------------------------- |
| Figma plugin name | Figma Design Relay     | Figma Design Relay (Dev: `<name>`)                   |
| Plugin id         | `figma-design-relay`   | `figma-design-relay-dev-<name>`                      |
| Port              | 1994                   | one of 1995–2019, the lowest free one                |
| Imported from     | `plugin/manifest.json` | `plugin/dist/manifest.json` (generated by the build) |
| MCP entry         | `figma-design-relay`   | `figma-design-relay-dev-<name>`                      |

## 1. Create the worktree and claim the slot

From the main checkout (which must never hold a slot):

```bash
git fetch origin
git worktree add ../figma-design-relay-<feature> -b feat/<feature> origin/main
cd ../figma-design-relay-<feature>
bun install && (cd server && bun install) && (cd plugin && bun install)
bun scripts/dev-slot.mjs            # or: bun scripts/dev-slot.mjs <name>
```

The script writes `.dev-slot.json` (gitignored) and prints the next steps. The name defaults to the
branch minus its `feat/`-style prefix; the port is the lowest one no other worktree's slot holds. If
`bun install` rewrites a `bun.lock` without a dependency change, `git checkout` it.

## 2. Build, import, register

```bash
(cd server && bun run build) && (cd plugin && bun run build)
```

- **Both builds read the slot.** The plugin dials the slot's port and the build writes the dev
  manifest to `plugin/dist/manifest.json`; the server listens on the slot's port without any
  environment variable. `VITE_FIGMA_DESIGN_RELAY_WS` set to anything else fails the build.
- **Figma:** Plugins → Development → Import plugin from manifest… → this worktree's
  `plugin/dist/manifest.json`. Import once; rebuilds hot-reload it.
- **MCP client:** add the entry the script printed beside the stable one and restart the client. The
  agent then sees the dev tools under their own server name (`mcp__figma-design-relay-dev-<name>__…`).
  Ask the user before editing their client config.

## 3. Work there

Everything for the task — code, tests, `server/.smoke/` probes — runs inside the worktree. The smoke
harness reads the slot too, so `node .smoke/call.mjs …` hits the dev relay, not the stable one.
Follow CLAUDE.md's workflow as usual; `finish-task` merges from here.

## 4. Tear down after the merge

Once `finish-task` has merged the branch into `main`:

1. Remove the Dev plugin from Figma's Development menu, and its entry from the MCP client config.
2. From the main checkout: `git worktree remove ../figma-design-relay-<feature>` and delete the
   branch. The slot file goes with the worktree, and its port is free for the next feature.
3. Rebuild the main checkout (`git pull`, both builds) so the stable plugin carries the feature.

A slot left behind is harmless but uses up a port and clutters the Development menu; `git worktree
list` shows what is still around.
